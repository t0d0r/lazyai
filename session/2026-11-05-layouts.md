# 2026-11-05 - dashboard layouts

## Done

- `v` cycles three dashboard layouts: split -> detail -> lists -> split
  (specs/tui.md, Layouts). lazyai starts in split, which is the
  dashboard as it was before; the choice is not saved.
  - split: lists left (a third, 32 to 56 columns), main panel right.
  - detail: compact list column, a fifth of the width with 24 to 32
    columns and never more than half the screen; the main panel gains
    16 columns at 120, 24 from 168 on. Compact rows keep the mark,
    kind, role and label and show `busy` only for busy agents; no CPU
    or memory.
  - lists: the lists take the whole width with full rows; the main
    panel is hidden. tab / shift+tab skip it; enter, ] / [ and the page
    keys answer "the lists layout hides the main panel; v shows it".
    Switching to lists from the main panel moves the focus to the list.
    No Screen capture runs while hidden, a late capture is dropped, and
    leaving lists captures again.
- The active layout shows in the status panel's bottom border
  (`split layout`), the message line on change, the `?` popup
  (`(now split)`), the x menu (`switch to the detail layout`) and the
  footer (`v layout`; the lists footer drops `[ ] tabs`).
- Status panel: two more narrow forms, `9 run, 3 busy` with the memory
  total only and then alone, so the counts are never cut in the
  detail column; `loading ...` is dropped when it does not fit.
- specs/tui.md: new Layouts section with rationale and breakpoints;
  Keys table gains `v`, and the focus-key paragraph that split the
  table moved below it. README dashboard section and key table, and
  specs/README.md, mention `v`.

## Decisions

- One cycle key rather than a key per layout: three layouts, and 1 2 3
  already pick the lists. Detail comes right after split because more
  room for Screen and Processes is the usual reason to switch.
- Detail keeps all three lists in a narrow column, not a strip above
  the main panel: keys, mouse and heights stay as in split, and the
  main panel keeps its full height.
- The role stays in compact rows, so two processes of the same model in
  one directory (engine and job) do not look the same.
- Lists hides the main panel and enter does not bring it back; only v
  changes the layout.
- Heights, selection, filters, tab and scroll are shared by all
  layouts; only widths and row contents change.
- No forced screen clear on a switch: every line is drawn to the full
  width in every layout (tested), so nothing of the previous layout can
  stay behind.

## Tests

40x10 to 200x60 and requires each line to be exactly the screen width;
TestLayoutCycle, TestLayoutStructure (widths, side-by-side corners,
compact and full rows, mouse), TestLayoutListsHidesMain (focus cycle,
hint keys, capture), TestLayoutNarrow (detail never wider than half or
than split for widths 30 to 250, equal to split under 50, counts not
cut), TestLayoutHints (help, footer). Each layout rule was checked by
breaking it on purpose: the tests fail.

The built binary was run in a private tmux server at 120x30: v cycles
the layouts, every captured line is 120 columns, the main panel starts
at column 40 in split and 24 in detail, and lists draws one column.
